# E2E Tests (Playwright)

End-to-end tests for critical flows per [Design/IMPLEMENTATION_ROADMAP.md](../../Design/IMPLEMENTATION_ROADMAP.md) Step 7.2.

## Prerequisites

- **PostgreSQL** running (e.g. `docker compose up -d` from repo root)
- **Backend** running before you run E2E (Playwright does not start it, to avoid hangs). In a separate terminal:
  ```bash
  cd backend && .venv/bin/uvicorn app.main:app --reload
  ```
- **Frontend** is started automatically by Playwright when you run `npm run test:e2e` (or run `npm run dev` yourself and Playwright will reuse it)

**Required for "Test sign in" and to avoid 429 (rate limit) on create route:** use the same secret in both places. The frontend sends `X-E2E-Secret` when these are set; the backend skips rate limiting for those requests.

- **Backend** `backend/.env`:
  ```bash
  E2E_TEST_SECRET=your-secret-here
  ```
  Restart the backend after adding or changing this.
- **Frontend** `frontend/.env.local`:
  ```bash
  VITE_E2E_MODE=true
  VITE_E2E_SECRET=your-secret-here
  ```
  Restart the frontend dev server after changing `.env.local` (or let Playwright start it via `npm run test:e2e`).

## Run E2E

From `frontend/`:

```bash
npx playwright install chromium   # first time only
npm run test:e2e
```

## Flows covered

- **create-route.spec.ts**: Sign in (test login) -> Create route -> View route (UAT-FR1, FR2)
- **upload-photo.spec.ts**: Sign in -> Create route -> Upload photo -> View route with photo (UAT-FR1, FR2, FR3)
- **browse.spec.ts**: Browse public routes -> Select route -> View route (UAT-FR4, FR5)

## Fixtures

- `fixtures/photo-with-gps.jpg`: Minimal JPEG with EXIF GPS (required for upload test). Generated by `backend/scripts/create_e2e_photo.py` if missing. Fixture files are **not** served to app users and are **not** in the production build (see `fixtures/README.md`).

**Visibility of E2E-created data:** E2E tests create routes and photos in the database. If you use the same DB as development, those records will appear in the app (e.g. browse). To avoid that, use a dedicated test database for E2E (set `DATABASE_URL` to a separate DB) or run the dev-data cleanup script after E2E (see `scripts/TEST_DATA_CLEANUP.md`).
